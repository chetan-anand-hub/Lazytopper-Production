On the CBSE marking requirement: **yes, it can be incorporated**, but there is an important limit. If you want “strict adherence with CBSE marking scheme published on the official website,” the safest source is the official CBSE Academics sample-paper and marking-scheme pages and PDFs. CBSE currently publishes Class X **Science**, **Mathematics (Basic)**, and **Mathematics (Standard)** sample question papers and marking schemes on its Academics site for the 2025–26 session. ([CBSE Academic][3])

But there is a practical caveat: **CBSE does not publish an official marking scheme for every arbitrary question you invent**. It publishes marking schemes for official/sample papers. So for your 900-question product, “strict adherence” can mean one of two things:

* **Strict official mapping**: only for questions that are actual CBSE/sample-paper questions with an official published marking scheme.
* **Derived CBSE-aligned marking**: for new/generated questions, you create marks-per-step using a rubric learned from official CBSE marking-scheme patterns, chapter weightage, answer style, and step allocation conventions. This can be highly aligned, but it is not literally an official CBSE marking scheme for that exact custom question. ([CBSE Academic][3])

So the correct product wording should be:

* **“Aligned to official CBSE marking-scheme patterns”** for custom/generated questions.
* **“Mapped to official CBSE marking scheme”** only when the question exists in an official CBSE source. ([CBSE Academic][3])

A good production architecture for you would be:

**Stage A: Step-mark generation**

* Input: question, subject, chapter, marks, question type.
* Output JSON like:

  * final answer
  * ordered steps
  * marks per step
  * examiner notes
  * accepted alternatives
  * diagram requirements
* Force the model to return structured output only.
* Add a rule engine that checks:

  * total marks add up correctly,
  * no step exceeds remaining marks,
  * mandatory theorem/law names appear where needed,
  * final answer is present,
  * unit/significant-label checks are present.
    This is where your “marks per step” requirement should live, not inside image generation. The image layer should simply **render** already-approved step data. That separation will improve consistency and reduce cost. ([OpenAI Developers][4])

**Stage B: Official-scheme grounding**

* Build a repository of official CBSE PDFs from the Academics site:

  * Class X Science marking schemes,
  * Class X Maths Standard marking schemes,
  * Class X Maths Basic marking schemes,
  * archived prior years too. ([CBSE Academic][3])
* Tag each official question by:

  * chapter,
  * cognitive skill,
  * answer style,
  * mark breakup pattern,
  * theorem/formula usage,
  * diagram requirement.
* For each new question, retrieve the closest official examples first, then generate the stepwise marking from those references.
  This is how you get much closer to true CBSE alignment.

**Stage C: Diagram/image rendering**

* Feed the approved structured solution to image generation.
* One prompt per image:

  * base question diagram,
  * step 1,
  * step 2,
  * final answer diagram.
* Include the marks label in the prompt, for example:

  * “Display a clean CBSE-style label on the top right: Step 2 — 1 mark”
  * “Use consistent alignment and typography across all steps.”
    OpenAI’s image APIs support generating images from prompts, and GPT Image is positioned for stronger instruction following and text rendering than older image models. ([OpenAI Developers][5])

For your use case, the cheapest robust architecture is usually:

* **Text/marking generation** with a text model using structured outputs.
* **Image generation** only after the text is approved.
* **Batch API** for bulk runs.
  This is cheaper than asking one image call to “figure out the pedagogy and the marking scheme itself.”

On cost, your new requirement adds a **text-generation and validation layer**, but that cost is usually still modest compared with image volume. The main extra cost comes from:

* retrieving/processing official marking-scheme references,
* generating structured stepwise mark breakdowns,
* possibly doing a second-pass validator call,
* then generating images.
  Batch can reduce the API cost for the batch-supported requests by **50% compared with synchronous APIs**. ([OpenAI Developers][2])

For a realistic 900-question system, I would budget in **three buckets**:

1. **Curriculum + marking intelligence**

   * ingest official CBSE marking-scheme PDFs
   * tag them by chapter/question type
   * create validator rules

2. **Per-question text generation**

   * structured solution steps
   * step-wise marks
   * scheme-alignment notes
   * review/validation pass

3. **Per-question images**

   * question diagram
   * each step diagram
   * final summary image

The image bucket will still usually dominate if you generate 4–6 images per question. The marking requirement mostly increases **engineering complexity** more than raw image cost.
