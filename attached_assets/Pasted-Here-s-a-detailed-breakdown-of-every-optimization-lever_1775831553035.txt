### Layer 1 — API optimisations (1–2 days, saves ~62%)

**Prompt caching on your CBSE system prompt** is your single biggest win. Every call to your tutor starts with the same block of text — chapter content, syllabus instructions, tutor persona. Adding `cache_control: {"type": "ephemeral"}` to that block makes it cost 90% less on every repeat hit. With 2,000 DAU doing 8 turns each, this alone saves roughly $400/month.

```js
"system": [{
  "type": "text",
  "text": "You are a CBSE Class 10 tutor. Chapter: Real Numbers...",
  "cache_control": {"type": "ephemeral"}  // ← one line change
}]
```

**Batch API for pre-generated content** gives you 50% off on anything that doesn't need to be live. Practice questions, visual explainers, and exam predictions can all be generated overnight and stored. Same output quality, half the API cost.

---

### Layer 2 — Static content library (3–5 days, saves additional ~50%)

CBSE Class 10 has a fixed syllabus — 15 Maths chapters and 5 Science subjects, roughly 160–200 key concepts total. You can generate everything once and serve it forever.

**Visual explainers:** Generate all ~180 interactive HTML widgets in one batch job (~$8 one-time). Store in Replit DB. Serve statically on request. Recurring cost for this feature: $0.

**Question bank pool:** Generate 80–100 MCQs and long-answer questions per chapter (~$12 total one-time). Randomly serve 10 per session. A student needs 8–10 sessions before seeing repeats — plenty of variety. Recurring cost: $0.

**Exam predictions:** Board exam patterns don't change weekly. Generate predictions twice a year (before March boards and October pre-boards), store and serve. This feature drops from ~$60/month to near zero.

After Layers 1 and 2, only the live chat tutor is generating real-time API calls.

---

### Layer 3 — Smart model routing (1–2 weeks, saves additional ~40%)

**Use Haiku for simple chat, Sonnet for complex reasoning.** "What is the formula for area of a circle?" doesn't need Sonnet — Haiku 4.5 handles it at 3× lower cost. Route based on query type and length:

```js
function selectModel(query, type) {
  if (type === 'factual' || query.length < 80)
    return 'claude-haiku-4-5-20251001';  // 3x cheaper
  return 'claude-sonnet-4-6';            // complex problems
}
```

**Truncate conversation history.** This is the biggest hidden cost most developers miss. If you're sending 10 turns of history with every message, you're paying for 10× the input tokens you actually need. For tutoring, the last 3–4 turns are all that matters for context. Slicing history from 10 to 4 turns cuts input tokens per chat message by ~60%.

### Layer 4 — Scale architecture (when you hit 5,000+ DAU)

**Semantic similarity cache** using pgvector (available on Replit's Postgres). Students ask the same questions in slightly different words constantly. A vector similarity check before each API call can serve 40–60% of chat queries from cache at near-zero marginal cost. Your cost per student actually falls as traffic grows.

**Shared prompt cache** is a structural advantage you already get for free — when 50–100 students are studying the same chapter simultaneously at peak hours, they all share the same cached system prompt. You pay the write cost once; everyone benefits. The more concurrent users per chapter, the better your effective cache hit rate.
