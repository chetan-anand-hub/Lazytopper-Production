Fix 1 — Visual diagrams are blank/missing in the tutor window
File: lazytopper/src/components/VisualExplainer.tsx
Line: 62

What's broken: When the tutor window opens on any topic (e.g. /app/topic-hub/10/Maths/trigonometry), the visual diagram area appears as a large blank white box. The VisualExplainer component does a HEAD request to verify the static HTML diagram file exists (files are at lazytopper/public/visuals/maths/.../filename.html). The HEAD check on line 62 also requires Content-Type: text/html in the response header — but Vite's dev server frequently omits that header on HEAD requests. When the check fails, the component falls into a slow AI-generation fallback (/api/generate-visual), which takes 10+ seconds and holds a white rgba(255,255,255,0.9) loading overlay at zIndex:2 covering the iframe the entire time. The user sees a blank white box.

Exact fix — change line 62 from:

if (res.ok && res.headers.get("content-type")?.includes("text/html")) {
  return;
}

to:

if (res.ok) {
  setLoading(false);
  return;
}

res.ok alone is sufficient — if the file exists (200 OK), trust it, clear the loading overlay immediately, and let the iframe's own onLoad event handle rendering.

Verify: Open /app/topic-hub/10/Maths/trigonometry, click Learn/Teach. The visual explainer at the top of the tutor pane should now show a dark-background interactive HTML diagram (navy gradient, not white). Take a screenshot.

Fix 2 — Tutor response is cut off mid-sentence
Files:

lazytopper/src/components/tutor/TutorDrawerV2.tsx — line 103
lazytopper/server/routes/mentorResponseBuilder.cjs — line 64
What's broken: The client-side fetch timeout (MENTOR_SERVER_TIMEOUT_MS) is set to 9 seconds. Gemini 2.5 Pro — the model used for all tutor responses — regularly takes 12–20 seconds to generate a complete conversational teaching response. The AbortController fires at 9 seconds, killing the connection mid-generation. Whatever partial text was buffered gets stored in state and rendered to the student as a sentence cut off in the middle (e.g. ending with "...looking up at a"). The student sees an incomplete, confusing explanation.

Fix 1 — increase timeout in TutorDrawerV2.tsx line 103:

// BEFORE
const MENTOR_SERVER_TIMEOUT_MS = 9_000;
// AFTER
const MENTOR_SERVER_TIMEOUT_MS = 28_000;

Fix 2 — increase max output tokens in mentorResponseBuilder.cjs line 64 (inside the conversational_teach handler):

// BEFORE
maxOutputTokens: 1600,
// AFTER
maxOutputTokens: 2500,

Fix 3 — Light mode is broken: navbar toggle missing + 819 hardcoded dark colors
Background on the theme system:

Theme context: lazytopper/src/context/ThemeContext.tsx
useTheme() returns { theme, toggleTheme, setTheme } where theme is "dark" | "light"
The theme is applied by setting data-theme="light" on document.documentElement
CSS variables are defined in lazytopper/src/styles.css:
Dark (:root default): --bg: #0a0a0a, --bg-card: rgba(255,255,255,0.03), --bg-card-border: rgba(255,255,255,0.06), --text: #ffffff, --text-muted: rgba(255,255,255,0.45)
Light ([data-theme="light"]): --bg: #f8fafc, --bg-card: #ffffff, --bg-card-border: #e2e8f0, --text: #1e293b, --text-muted: rgba(30,41,59,0.5)
The problem: 57 component files contain 819 occurrences of hardcoded rgba(255,255,255,...) inline styles that never change when the theme switches. In light mode, this produces invisible white-on-white text, borders, and cards across the entire app.
Part A — Add the toggle to the navbar (App.tsx)

The toggle currently only exists buried inside the Profile/ME page. Students have no way to switch themes from the dashboard or any other page.

In lazytopper/src/App.tsx:

Add import near the top: import { useTheme } from "./context/ThemeContext";
