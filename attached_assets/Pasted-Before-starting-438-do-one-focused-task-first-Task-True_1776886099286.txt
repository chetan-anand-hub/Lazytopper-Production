## Required implementation behavior

### A. Data/config shape

Refactor worksheet preset config so section scope can represent:

* one section
* all sections
* multiple sections

You may use whichever implementation is cleanest, for example:

* `sectionFilter: "All" | SectionKey`
* plus `sectionFilters: SectionKey[]`
  or
* a single unified array-based representation
  or
* another small explicit structure

Choose the cleanest minimal-change version, but the result must support:

* `["A","B"]`
* `["C","D","E"]`
* all sections

### B. Generation logic

When generating a worksheet:

* generate the candidate question set
* filter it according to the selected section scope
* preserve difficulty behavior already implemented
* preserve count behavior
* do not silently ignore the section scope

### C. Empty / low-result handling

If filtering leaves zero questions:

* show a clear error state

If filtering leaves fewer questions than requested:

* do **not** silently pad with wrong sections
* either:

  * return the smaller truthful set and communicate it clearly
  * or implement a clean fallback rule and explain it explicitly in code/comments/output

Preferred behavior:

* keep the set truthful to the chosen sections
* do not dilute the scope just to hit the count

### D. Ready-screen summary

`WorksheetReady` must accurately show:

* subject
* topic
* difficulty
* section scope
* question count

Examples:

* `Sections A + B`
* `Sections C + D + E`
* `All sections (A–E)`

### E. Preset copy

Update preset descriptions so they match the new real behavior exactly.

Expected copy direction:

* Board exam mix → `All sections A–E · All difficulty · 25 questions`
* Quick drill → `Sections A–B · All difficulty · 15 questions`
* High-marks focus → `Sections C–E · Hard difficulty · 20 questions`

You may refine wording slightly, but keep the meaning exact.

### F. Custom mode

Keep custom mode working.

If custom mode currently supports only:

* one section
  or
* All sections

that is acceptable unless a very small clean improvement can add custom multi-select without scope creep.

Important:
this task’s mandatory requirement is **preset multi-section support**.
Custom multi-select is optional only if it is genuinely small and low-risk.
